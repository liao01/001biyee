# 仓库密钥与敏感信息历史清理设计

## 目标

安全清理 `liao01/001biyee` 当前版本及全部 Git 历史中的密钥和敏感信息，阻止同类内容再次进入版本库，并在不覆盖当前本地未提交改动的前提下更新 GitHub 远端历史。

## 已确认范围

清理对象包括：

- 数据库、Redis、AI、地图、邮件等服务的账号、密码、API 密钥和授权码；
- JWT 签名密钥、请求令牌及历史测试令牌；
- 日志文件及日志中的令牌、用户资料和运行数据；
- SQL 导出中的真实数据、手机号、邮箱、验证码、密码哈希和用户内容；
- 用户上传的头像、图片及其他运行期文件；
- 配置、源码、HTTP 请求样例和测试代码中的硬编码敏感值；
- 所有远端分支、标签及其可达历史中的上述内容。

数据库脚本只允许保留表结构、索引和约束。示例配置只允许使用无效占位符或环境变量引用。

## 事实源与配置策略

运行时凭据的唯一正式事实源为部署环境或本地环境变量，Git 仓库不保存真实值。

- Spring 配置从环境变量读取，并提供无敏感值的默认开发配置或显式必填项。
- 前端环境文件只保留非敏感公开配置；敏感凭据不得进入前端构建产物。
- `.env.example` 只记录变量名和无效占位符。
- `.gitignore` 统一排除真实环境文件、日志、上传目录、数据库数据导出和构建产物。
- 历史兼容只允许通过变量名映射实现，不保留旧密钥或旧敏感值。

## 执行架构

### 1. 保护当前工作区

当前 `master` 相对远端同时领先和落后，并存在大量未提交文件。历史净化在独立临时镜像中完成，不对当前 `.git` 执行重置、清理或历史改写，也不删除当前未跟踪文件。

执行前记录：

- 远端所有引用；
- 当前远端默认分支提交；
- 当前本地分支提交；
- 工作区状态摘要。

记录中不得包含密钥原文。

### 2. 构造安全快照

从远端全部引用创建独立镜像，并在临时工作副本中生成安全的当前版本：

- 删除版本控制中的日志、上传文件和含真实记录的数据库导出；
- 如需保留数据库脚本，将其收敛为仅含结构的脚本；
- 将硬编码凭据替换为环境变量；
- 删除源码和请求样例中的真实邮箱、手机号、令牌及个人测试数据；
- 添加脱敏示例配置、忽略规则和安全说明。

不自动把当前脏工作区的未提交内容加入远端清理结果，避免误发布本地数据。

### 3. 改写全部历史

使用 `git-filter-repo` 对全部分支和标签执行确定性改写：

- 对始终不应受版本控制的路径执行全历史删除；
- 对必须保留的文本文件执行已识别敏感值替换；
- 对历史 SQL 数据导出优先整文件删除，避免结构化数据漏删；
- 清理完成后移除旧引用并执行本地对象回收，使临时镜像自身不再保留旧对象。

历史改写会改变相关提交 SHA。远端更新使用带租约或逐引用校验的强制推送；若远端在扫描后发生新提交，停止推送并重新评估，不覆盖未知更新。

### 4. 验证

验证必须覆盖工作树和所有改写后的引用：

- 已知密钥指纹零命中；
- 通用密钥模式零有效命中；
- 被禁止的日志、上传和数据导出路径零命中；
- SQL 中不存在 `INSERT`、手机号、邮箱、验证码或密码哈希等真实记录；
- 配置和源码中不存在硬编码凭据；
- 所有分支和标签均可解析；
- 项目配置加载测试及现有相关测试通过；
- 执行第二次扫描，确认清理规则可重复且结果无新增差异。

扫描报告只记录类别、路径、引用和数量，不记录秘密原文。

### 5. 更新远端与本地交接

验证通过后强制更新 GitHub 全部受影响的分支和标签，并再次从远端克隆进行独立复验。

当前本地目录不会被自动删除。由于其 `.git` 和未提交文件仍可能含敏感内容，远端更新成功后：

- 建议把需要保留的非敏感本地改动以补丁方式迁移到全新克隆；
- 迁移前扫描补丁，不携带密钥、日志、数据库记录或上传文件；
- 用户确认迁移完成后，再安全移除旧本地副本。

## 凭据吊销与轮换

历史删除不能使已泄露凭据失效。远端净化后必须在对应服务商完成：

- 数据库和 Redis 凭据轮换；
- AI、地图等 API 密钥吊销并重建；
- 邮箱 SMTP 授权码吊销；
- JWT 签名密钥轮换，并使现有会话失效；
- 其他被扫描识别出的访问令牌吊销。

新凭据仅写入部署环境或本地未跟踪环境文件，不写入提交、Issue、PR、日志或清理报告。

## 回滚与失败处理

- 强制推送前保留仅本地、访问受限的引用映射和远端提交 SHA，映射不含文件内容或密钥；
- 若验证失败，不推送远端；
- 若远端引用发生变化，不强制覆盖，重新拉取并重做改写；
- 强制推送后如发现漏项，立即吊销相关凭据并再次执行全历史改写；
- 不创建包含原始秘密内容的普通备份包，避免新增泄露副本。

## 完成标准

只有同时满足以下条件才可宣告完成：

1. 改写后的全部分支和标签通过敏感信息扫描；
2. GitHub 远端已更新，并从远端重新克隆复验通过；
3. 当前版本通过必要构建或测试；
4. 防回流规则已进入仓库；
5. 已向用户提供不含秘密原文的凭据轮换清单；
6. 已明确告知协作者旧提交 SHA 和旧克隆不可继续使用。
