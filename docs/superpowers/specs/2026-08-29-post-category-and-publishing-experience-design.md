# 帖子分类与发布体验收敛设计

## 背景

当前用户端存在五类相互关联的问题：发现页的“推荐、最新”和内容分类混在同一组静态标签中；帖子卡片只显示“旅行记录”占位；发布页使用另一套“美食、景点、旅行、攻略”标签；顶部栏、侧边栏和个人页面存在重复的“发布”或“我的”入口；发布历史因 MyBatis 参数名不一致而查询失败。帖子详情弹层还存在标题被顶出可视区域、图片过大、正文与互动层级失衡的问题。

本设计在现有用户端视觉体系和帖子详情 deep module 边界内，建立正式分类事实源，收敛发布与个人入口，重排详情和发布页面，并修复发布历史查询。现有帖子详情以 `postId` 为唯一入口的架构决策保持不变，参见 `docs/adr/0001-post-detail-module-seam.md`。

## 目标

- 明确区分发现页视图控制与帖子内容分类。
- 以 MySQL 分类表作为唯一正式分类事实源。
- 新帖子必须选择且只能选择一个启用分类。
- 发现卡片、详情、搜索和发布历史消费同一分类字段。
- 详情弹层采用已确认的 A 方案双栏布局，发布页采用双栏工作流。
- 桌面端的“发布”和“我的”各保留一个主入口。
- 修复发布历史参数绑定错误并增加防回归测试。
- 提供可重复执行、可 dry-run、可统计差异的历史数据迁移。

## 非目标

- 不改变登录协议、用户关注语义、帖子互动语义或管理端页面。
- 不把“推荐、最新”写入帖子分类。
- 不在本次实现推荐算法；“推荐”沿用后端默认内容顺序，“最新”明确按发布时间倒序。
- 不删除现有 `tag`、`post_tag` 表；它们作为普通标签兼容层保留，但不再是分类事实源。
- 不改变帖子详情模块仅通过 `postId` 读取正式详情的外部接口。

## 正式领域口径

### 发现视图

- `推荐`：发现页默认视图，使用后端默认内容顺序。
- `最新`：按 `post.create_time DESC` 排序。

二者只控制列表呈现，不属于帖子数据。

### 帖子分类

正式分类只有三项：

| 编码 | 中文名称 | 默认排序 |
| --- | --- | ---: |
| `CITY_WALK` | 城市漫游 | 10 |
| `NATURAL_SCENERY` | 自然风光 | 20 |
| `FOOD` | 美食 | 30 |

分类编码是跨数据库、接口和前端状态传递的稳定标识；中文名称由数据库配置返回，不在调用方复制维护。

## 数据模型

### `post_category`

新增分类字典表：

- `code varchar(32)`：主键，稳定分类编码。
- `name varchar(50)`：面向用户的分类名称。
- `sort_order int`：展示顺序。
- `enabled tinyint(1)`：是否允许新发布内容选择。
- `create_time datetime`、`update_time datetime`：审计时间。

初始化脚本采用 upsert 语义：新增缺失分类、更新名称和排序、保留已有主键引用。停用分类不出现在发布选择器中，但历史帖子仍可读取名称。

### `post.category_code`

在 `post` 表新增可空的 `category_code varchar(32)`，外键指向 `post_category.code`。

数据库字段在历史迁移完成前保持可空，以避免把无法明确分类的旧帖子强行归入错误类别。服务层对所有新发布请求强制校验非空、存在且启用。历史数据清理完毕后，可在独立迁移中评估改为 `NOT NULL`，本次不自动执行该收紧操作。

### 旧标签兼容

`tag` 和 `post_tag` 继续保存历史普通标签。新发布流程不再根据用户提交的任意名称创建分类标签，也不再通过 `GROUP_CONCAT(tag.name)` 推断分类。

## 历史数据迁移

新增 SQL 迁移脚本，包含以下阶段：

1. 创建或收敛 `post_category` 三项正式分类。
2. 新增 `post.category_code` 和索引、外键；重复执行时不得重复创建。
3. dry-run 输出：总帖子数、已有分类数、按旧标签可唯一映射数、冲突数、无法映射数和待处理帖子 ID。
4. 仅执行明确映射：旧标签 `美食` 映射 `FOOD`，旧标签 `景点` 映射 `NATURAL_SCENERY`，只含 `旅行` 或 `攻略` 且无更具体分类时映射 `CITY_WALK`。
5. 同时命中多个不同目标分类或没有可识别标签的帖子保持 `NULL`，输出精确 ID 供人工确认，不按标题或正文猜测。
6. 执行后再次输出三类数量、空分类数量、非法编码数量和外键一致性统计。

迁移脚本不得删除旧标签或帖子。恢复策略为在执行前备份 `post.id/category_code`，需要回滚时仅恢复该列并保留新分类表；生产或共享数据库执行前仍需确认目标环境和备份位置。

## 后端接口与数据流

### 分类查询

新增 `GET /web/post/categories`。

响应内容为启用分类的有序列表：

```json
[
  { "code": "CITY_WALK", "name": "城市漫游" },
  { "code": "NATURAL_SCENERY", "name": "自然风光" },
  { "code": "FOOD", "name": "美食" }
]
```

前端发布页和发现页分类标签均消费此接口。发现页额外在本地组合“推荐、最新”两个非分类视图入口。

### 发布帖子

`POST /web/post/post-save` 请求增加必填 `categoryCode`。服务端继续从 `LoginMemberContext` 获取作者并强制写入公开状态，不信任请求中的 `userId` 和 `status`；前端停止发送这两个冗余字段。`locationId` 在现有保存链路中未落库，本次前端也停止发送固定值 `3`。

保存事务按以下顺序执行：验证登录用户、验证分类、验证标题正文与图片、保存帖子、保存图片。任一环节失败时整体回滚。

### 列表、搜索、详情和历史

以下响应统一增加 `categoryCode` 和 `categoryName`：

- 发现列表 `post-findAll`。
- 关键词搜索 `post-search`。
- 公共帖子详情 `detail`。
- 用户发布历史 `post-User-search`。
- 用户帖子列表、收藏列表和浏览历史所消费的帖子响应。

查询直接关联 `post.category_code -> post_category.code`。卡片和详情不得再从 `tagTitle` 或前端常量推断分类。

发现列表支持可选 `view` 和 `categoryCode` 参数：`view=LATEST` 时显式按发布时间倒序；设置 `categoryCode` 时只返回对应分类。无参数时为推荐视图。无效或停用分类返回明确业务错误，不静默回退。

## 发布历史错误根因与修复

错误栈显示 `PostMapperCust.selectPostDetailsByUserId` 的 Java 参数使用 `@Param("id")`，而 XML 使用 `#{userId}`。MyBatis 只能看到 `id` 和 `param1`，因此抛出 `BindingException: Parameter 'userId' not found`。

修复方式是将 Mapper 方法参数统一为 `@Param("userId") Long userId`，XML 保持 `#{userId}`。同一 Mapper 中按用户查询的方法一并检查并统一显式参数名，防止相同漂移继续存在。发布历史表格使用 `postId` 作为 `rowKey`，标题可打开统一帖子详情。

## 前端设计

### 帖子详情双栏弹层

- 桌面端弹层最大宽度约 `1360px`，最大高度 `92vh`，整体不超出当前视口。
- 主布局约为 58% 图片画廊和 42% 阅读与互动区。
- 右栏从上至下排列分类、标题、作者与发布时间、正文、互动和评论；标题必须完整进入首屏，不允许被顶部裁切。
- 多图保持稳定宽高比，当前图完整可见并提供清晰的切换方式。
- 弹层内部滚动，关闭按钮固定在可见位置；背景点击和 Escape 仍可关闭。
- 小于 `768px` 时切为单列：图片、分类标题、正文互动、评论顺序排列。

### 发布页双栏工作流

- 左栏负责标题、正文和最多八张图片，保留图片预览与删除。
- 右栏为发布设置，只包含从分类接口加载的单选分类、内容检查提示和唯一发布按钮。
- 标题、正文、至少一张图片和分类全部有效后才允许提交。
- 加载分类失败时展示局部错误和重试，不允许用硬编码分类继续发布。
- 发布成功后清空表单并给出成功反馈；重复点击由 pending 状态阻止。

### 发现页与帖子卡片

- 发现页顶部先展示“推荐、最新”，随后展示后端返回的正式分类。
- 切换视图或分类时更新列表加载状态；请求失败保留当前选择并显示错误。
- 帖子卡片图片左下角显示 `categoryName`，删除“旅行记录”默认占位。
- 分类为空的历史帖子不伪造正式分类；卡片显示中性的“待分类”，便于发现迁移残留。

### 入口收敛

- 桌面端左侧导航保留“发布”和“我的”，作为两个功能的唯一主入口。
- 顶部栏移除“发布旅行”按钮。
- 顶部账户菜单移除“个人资料”，保留登录、修改资料和退出登录。
- `UserProfile`/`ProfileHeader` 移除重复的发布按钮和发布事件。
- 移动端继续由底部导航提供“发布”和“我的”；顶部仅保留品牌、搜索和账户状态所需控件。

### 发布历史

- 保留表格型管理界面，标题、分类、发布时间和删除操作层级清晰。
- 标题点击打开统一帖子详情弹层。
- 删除采用现有软删除，不扩大为物理删除。
- 修正初始分页页码为 1，行键使用 `postId`。
- 提供加载、空状态、接口失败和删除失败反馈；移动端允许表格横向滚动或切换紧凑行布局，不裁切主要操作。

## 错误处理

- 分类接口失败：发布页禁用提交并允许重试；发现页保留“推荐、最新”但不伪造分类项。
- 发布分类无效或已停用：后端返回业务错误，前端保留编辑内容并提示重新选择。
- 列表中历史帖子无分类：返回空分类，前端显示“待分类”，迁移统计持续报告。
- 发布历史查询失败：页面展示明确错误而不是误报为空列表。
- 图片处理或任一数据库写入失败：发布事务回滚，不留下半成品帖子、图片或分类关联。

## 测试策略

### 后端

- 分类查询只返回启用分类并按 `sort_order` 排序。
- 发布请求缺少分类、分类不存在或分类停用时失败且不写入帖子。
- 合法分类随帖子保存，并在列表、搜索、详情和历史响应中返回。
- MyBatis 用户发布历史查询使用 `userId` 参数并能返回分页结果。
- 按推荐、最新和分类查询的条件与排序符合接口契约。
- 发布事务在图片处理失败时回滚。

### 前端

- 发布页从分类接口加载单选项，未完成必填项时按钮禁用。
- 发布请求只发送正式字段和 `categoryCode`，pending 期间不重复提交。
- 发现页把“推荐、最新”与正式分类分开，并按选择发送正确查询参数。
- 卡片显示 `categoryName`，空分类显示“待分类”。
- 顶部发布按钮、账户菜单个人资料项和个人页发布按钮不存在；侧边栏入口仍可用。
- 帖子详情存在桌面双栏结构和移动单列断点，关闭、互动和评论原有行为不回退。
- 发布历史成功、空、失败、分页、打开详情和软删除行为均有覆盖。

### 视觉与集成验证

- 运行后端测试、前端 Vitest 和前端生产构建。
- 使用浏览器验证发现筛选、发布、详情、发布历史和个人页入口。
- 检查至少 `1440px` 桌面、当前截图尺寸和小于 `768px` 移动视口。
- 将已确认的 A 方案视觉稿与最终浏览器截图并排检查：首屏层级、双栏比例、分类位置、按钮唯一性、文字尺寸、图片裁切、弹层滚动和移动端无横向溢出。

## 验收标准

- 数据库只配置三项启用正式分类，“推荐、最新”不进入帖子数据。
- 新发布帖子必须选择一个正式分类，卡片、详情和历史显示同一分类。
- 发现页可切换推荐、最新和三个分类，且请求与页面状态一致。
- 桌面详情弹层采用已确认双栏布局，标题、正文、互动和评论均可正常访问。
- 发布页采用双栏工作流且仅有一个发布按钮。
- 桌面端“发布”和“我的”各只有一个主入口。
- 发布历史不再出现 MyBatis `userId` 参数绑定错误。
- 历史迁移可 dry-run、可重复执行并报告未分类残留。
- 前后端自动化测试和构建通过，桌面与移动浏览器检查无主要视觉或交互缺陷。
