# 旅分享用户端体验改版设计

## 目标

将用户端重构为以旅行内容浏览与互动效率为主线的统一产品体验，同时提高发现、阅读、发布、收藏、关注、地图和 AI 助手页面的视觉一致性。

## 范围

- 用户端应用外壳：顶部栏、侧边导航、登录入口和响应式导航。
- 内容链路：发现、帖子详情、发布、发布历史、浏览历史、收藏。
- 用户链路：个人资料、资料编辑、作者主页、粉丝数据。
- 旅行工具：地图、旅游助手。
- 不修改后端接口、数据库结构、认证协议和管理端页面。

## 视觉方向

- 主背景使用纯白 `#ffffff`，辅助背景使用冷灰 `#f6f7f9`。
- 品牌强调色沿用珊瑚红 `#ff3b4f`，正文使用炭黑 `#17181c`。
- 图片是主要视觉载体；界面不依赖大面积渐变、重阴影或嵌套卡片。
- 圆角控制在 10–16px，边框轻且统一，阴影仅用于浮层和悬浮反馈。
- 中文界面采用清晰的标题、正文、说明三级排版；控件文字显式设置字号和字重。
- 图标保持统一的细线风格，地点和路线可使用少量地图线条作为品牌图形。

## 信息架构

桌面端使用固定顶部栏和紧凑左侧导航，内容区按页面需要切换为开放内容画布、阅读栏或工具画布。移动端隐藏桌面侧栏，核心入口进入底部导航；搜索、发布和账户操作保留在顶部。

发现页以标签导航、瀑布流内容和目的地线索为核心。帖子详情页以图片与正文阅读为核心，互动和作者信息在桌面端保持可见。个人空间、收藏和历史页共用同一套页头、标签、筛选和内容列表。地图和 AI 助手沿用同一应用外壳，但采用适合工具的全高画布。

## 组件边界

- `AppShell`：统一顶部栏、侧栏、移动导航和内容容器。
- `PostPreview`：发现页使用的图片帖子预览。
- `ContentListPage`：发布历史、浏览历史和收藏的共用页面骨架。
- `ProfileHeader`：个人资料和作者主页的共用身份区。
- 页面级组件继续拥有现有接口请求和业务状态，视觉组件不成为新的业务事实源。

## 交互与状态

- 所有按钮、导航、标签和卡片具备 hover、focus-visible、selected 和 disabled 状态。
- 搜索、登录、收藏、点赞、关注、评论、发布和地图交互继续消费现有接口。
- 未登录访问受限功能时继续调用现有登录弹窗。
- 空状态、加载状态和错误状态使用统一的轻量反馈，不用空白页面代替。
- 动效控制在 160–240ms，并尊重 `prefers-reduced-motion`。

## 响应式

- 大屏内容最大宽度 1440px；常规桌面保证 1280px 可用。
- 小于 1100px 时收窄侧栏和辅助栏；小于 768px 时切换移动导航与单列内容。
- 图片使用稳定宽高比和 `object-fit: cover`，避免布局跳动。
- 地图和 AI 页面在移动端保持主要操作区可用，不允许横向溢出。

## 验收标准

- 所有用户端路由均使用统一设计变量和应用外壳。
- 发现、详情、个人空间三个核心页面与已确认概念在结构、层级、色彩、排版和间距上保持一致。
- 所有原有核心操作仍可触发，现有自动化测试通过。
- `npm run build` 与 `npm test` 通过。
- 桌面端和移动端完成浏览器视觉检查，无主要内容裁切、横向滚动或不可读控件。
