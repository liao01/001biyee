# 领域文档

本仓库采用 single-context 结构。

## 开始分析代码前

应读取：

- 根目录 `CONTEXT.md`
- 与当前工作范围相关的 `docs/adr/` 文档

文件不存在时继续工作，不需要提前创建。`domain-modeling` 会在产生正式术语或架构决策时按需创建。

## 文件结构

```text
/
├── CONTEXT.md
└── docs/
    └── adr/
```

## 使用领域词汇

任务标题、重构建议、假设和测试名称中的领域概念，应使用 `CONTEXT.md` 定义的名称。不要改用词汇表明确排除的同义词。

如果所需概念尚未出现在词汇表中，应重新确认该概念是否符合项目语言；确有缺口时，交由 `domain-modeling` 补充。

## 标记 ADR 冲突

如果某项输出与现有 ADR 冲突，必须明确指出并说明重新讨论的原因，不得静默覆盖原有决策。
