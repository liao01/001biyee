# 刷新 Cookie 的跨域边界处置

## 最小证据

#16 接入 Cookie 会话时发现，既有 `CorsConfig` 允许任意来源并允许携带凭据。隔离 MockMvc 测试使用无状态处理器确认，不可信来源的 POST 预期被拒绝，修复前却进入处理器并返回成功。该组合在浏览器允许携带 Cookie 的情形（包括同站不同源）可能暴露会话接口，不能依靠 SameSite 替代来源限制。

本次没有操作真实账户、投递邮件、访问第三方站点或构造外部攻击流程；完整深度安全扫描仍未获授权。

## 本地修复

`CorsConfig` 只接受正式 `app.public-url` 的来源部分，部署子路径不进入来源比较。该配置与邮件跳转地址共用既有事实源，不新增独立来源列表或通配符后备规则。`IdentityCorsTests` 验证受信任来源的凭据预检成功、不可信来源及不透明来源不能进入处理器。

生产前后端及管理端按既有同站反向代理部署。开发时前端地址必须与该配置一致；localhost 和回环 IP 是不同来源，不允许通过恢复通配符解决配置不匹配。若要新增独立管理端来源，应先明确可信地址及配置归属，再补配置和边界验证。

本地修复不等于生产更新。未推送或部署，也未撤销线上会话；完整身份联调和最终安全门禁完成前禁止合并或发布。
