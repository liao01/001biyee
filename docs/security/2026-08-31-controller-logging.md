# 控制器凭据日志风险处置记录

## 证据与影响

2026-08-31 在 #15 邮箱身份接入前检查到：旧 `LogAspect` 对所有控制器调用序列化请求参数和返回对象，仅排除两个无关字段。登录响应中的令牌、请求中的标量凭据和密码字段可以进入应用日志。该路径存在高风险，修复与验证完成前禁止合并或部署该身份变更。

复现只在隔离的 MockMvc 测试中使用随机生成的合成值，没有读取真实日志、用户密码或线上令牌，没有发送外部请求。

## 本地修复

- 通用日志只保留方法、处理器和耗时，不序列化请求、响应、Cookie、参数或异常对象。
- 请求关联标识继续消费现有拦截器，不增加第二套标识规则。
- [ControllerLoggingTests](../../business/src/test/java/com/jiawa/lyw/security/ControllerLoggingTests.java) 从 HTTP 接口验证响应仍正常，同时检查请求体、标量参数和响应令牌不出现在日志。
- 定向回归 13 项通过；这不是对全部日志链路的深度安全扫描结论。
- 随后的后端全量回归 53 项通过，Python 回归 48 项通过，当前工作树与可达 Git 历史秘密扫描均为 0 项发现。
