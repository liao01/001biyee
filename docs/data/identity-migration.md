# 邮箱身份迁移

本记录覆盖 #15 的数据库迁移部分，不代表邮箱注册、验证、登录等应用链路已交付。

## 事实源与兼容边界

- 空库初始化结构：[sql/travel_share.sql](../../sql/travel_share.sql)。只用于空库，不可对已有业务库执行。
- 旧库升级及数据归一化：[20260829_member_email_identity.sql](../../sql/migrations/20260829_member_email_identity.sql)。迁移脚本是升级行为的事实源。
- 测试运行参数：[migration_specs.py](../../tests/scripts/migration_specs.py)。测试只使用回环 MySQL 中带随机批次后缀的隔离库。
- 身份结构由会员账户关联一次性邮件令牌和刷新会话。数据库只保存令牌摘要，不保存原始令牌；密码凭据由新身份模块读取。
- `member.mobile`、`member.password` 是显式历史兼容字段，不供新的身份流程写入。首次成功登录升级凭据时，应清除该账户历史密码副本；本迁移不预先移除尚未验证成功的历史凭据。

## 执行前

1. 确认目标库、维护窗口与该环境的迁移授权。测试通过不授权生产或共享库写入。
2. 停止旧账户注册和密码修改写入，备份会员表及已有身份表；备份必须存入项目规定的受保护目录，不得提交 Git。
3. 使用现有受保护的 MySQL 凭据配置连接目标库，不在命令参数、日志或文档中填写密码。
4. 默认直接执行迁移文件为 dry-run；不会更改正式表结构或业务数据。临时候选表仅存于当前连接，脚本结束或连接断开时清理。

## 报告与执行

执行同一 SQL 会话前，设置 `@apply_member_email_identity_migration = 1` 才会应用迁移；未设置或设为 0 都只报告。

报告只包含数量，不输出邮箱、密码或令牌：

| 指标 | 含义 |
| --- | --- |
| `eligible_email_rows` | 尚无正式邮箱、且规范化后没有归属冲突的可迁移账户数 |
| `manual_email_binding_rows` | 无法自动绑定邮箱的账户数，含邮箱格式不匹配及冲突 |
| `conflicting_email_rows` | 待迁移候选中规范化邮箱存在多个归属的数量，是待绑定数的子集 |
| `identified_account_rows` | apply 后已有正式邮箱的账户数 |
| `email_binding_required_rows` | apply 后处于明确待绑定状态的账户数 |
| `legacy_password_rows` | 尚需在成功登录时升级密码算法的账户数 |
| `missing_identity_tables` | apply 后身份令牌/会话表的缺失数量，应为零 |

冲突不会自动合并账户或选择邮箱归属；原始账户 ID 和社区关联保持不变。无法识别邮箱的账号不会生成虚假邮箱。已升级密码和已停用状态不会被覆盖。

应用后再次 dry-run，正常情况下可自动迁移数为零；待绑定和历史密码数量可以非零，分别等待经核验的绑定流程和成功登录升级。若仍有可自动迁移项、缺表或 SQL 错误，不得报告迁移完成。

## 中断与恢复

MySQL DDL 会隐式提交，因此迁移不是一个可整体回滚的事务。脚本逐项检查结构，允许在 DDL 中断后重新执行；重复 apply 不重新覆盖已迁移的邮箱或密码。

发生错误时保持写入暂停，核对错误与当前结构，优先修复原因后重跑。若必须整体恢复，先保存故障后的受保护备份，再在隔离恢复库验证维护窗口前备份，核对会员数量与关联完整性，取得恢复授权后切换；不要直接删除新列或覆盖活跃库。若新身份流程已产生新账户/会话，应先制定增量数据保留方案，不能直接恢复旧快照。

## 验证

运行 `python -m unittest tests.scripts.test_member_email_identity_migration -v`，覆盖真实 MySQL 上的只读预演、重复应用、规范化冲突、既有邮箱归属、停用账户保护、部分 DDL 恢复、令牌摘要结构以及空库/升级结构一致性。测试库由上下文管理器精确删除；测试不向实际用户发送邮件。
